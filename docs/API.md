# API Contract

> Owner: **M1** (conventions). Each section is owned by the app owner shown.
> The **live, authoritative schema** is OpenAPI at `/api/schema/` (Swagger UI: `/api/docs/`), generated by drf-spectacular. The frontend generates TypeScript types from it (`npm run gen:api`), so field names in this doc and in the code must match.
> Changing a field name = team message + update this doc + regenerate types in the same PR.

## Conventions
- Base path `/api/`. JSON only. **snake_case** fields. Trailing slash on every route (Django default).
- **Auth**: Django session cookie (`cadence_session`, httpOnly, SameSite=Lax, Secure in prod) + CSRF. The frontend calls `GET /api/auth/csrf/` once, then sends `X-CSRFToken` on every unsafe request. In prod the browser talks to the Vercel origin and Next rewrites `/api/*` to Render, so everything is same-origin.
- **Money** is serialized as a **string** (`"1180.00"`) to avoid float rounding. Display with `Intl.NumberFormat('en-IN', {style:'currency', currency:'INR'})`.
- Dates are `YYYY-MM-DD`; timestamps are ISO-8601 UTC.
- **Pagination** (every list): `?page=1&page_size=20` (max 100) →
  ```json
  {"count": 5321, "next": "…?page=2", "previous": null, "results": [ … ]}
  ```
- **Filtering / search / ordering** (django-filter + DRF): `?status=active&customer=12&search=acme&ordering=-created_at`.
- **Errors** (one shape everywhere, from `core.exceptions.handler`):
  ```json
  {"error": {"code": "validation_error", "message": "Please fix the highlighted fields.",
             "field_errors": {"email": ["Enter a valid email address."]}}}
  ```
  | HTTP | code examples |
  |---|---|
  | 400 | `validation_error`, `invalid_transition`, `quotation_expired`, `overpayment`, `invoice_not_payable`, `plan_unavailable` |
  | 401 | `not_authenticated` |
  | 403 | `permission_denied` (wrong role) |
  | 404 | `not_found` (also returned for objects outside a customer's scope, so they can't tell whether a record exists) |
  | 429 | `throttled` (login, signup, password reset) |
- **Server-Timing**: every `/api/` response carries `Server-Timing: db;dur=…;desc="N queries", app;dur=…` (frontend reads it via `performance.getEntriesByType("resource")`).
- **cost_price** is returned to admin/staff only; never in customer-visible payloads.
- **Roles**: `A` admin · `S` staff · `C` customer (scoped to own records).

## Ask Cadence (optional)
| Method | Path | Roles | Notes |
|---|---|---|---|
| GET | `/api/assistant/status/` | A,S | `{enabled: boolean}`; enabled only when all three assistant environment variables are set |
| GET | `/api/assistant/ask/?q=...` | A,S | 1–300 character question; 10 attempts per user per 60 seconds; returns `{answer, tool, numbers}` |

`tool` is `summary`, `aging`, `revenue_series`, `status_breakdown`, `pipeline`, or
null for unsupported questions (with a capability explanation and null numbers).
Only the selected existing analytics aggregate runs; no SQL or customer rows are
sent to the provider. Personal-lookup questions are refused locally; unknown words
in question text are redacted using a fixed finance vocabulary before either call.
This deliberately limits supported wording rather than forwarding personal details.
Summary uses default/all-time scope, revenue series the last
12 months; aging/status/pipeline are current. No custom filters or customer lookups.
Money remains decimal strings. Both responses are private/non-cacheable. GET also
works for read-only demo admin/staff accounts.

Configure server-only `ASSISTANT_API_KEY`, `ASSISTANT_API_URL` (full OpenAI-compatible
HTTPS chat completions endpoint) and `ASSISTANT_MODEL`. Redirects are refused so
authorization cannot be forwarded to another host. With no configuration the Insights
box stays hidden. Each of the two provider calls has a 10-second timeout. Provider
failures return 503 `assistant_unavailable`, disabled asks 503 `assistant_disabled`,
invalid tool selections 400 `assistant_invalid_tool`, and rate limits 429 `throttled`,
all in the standard error shape. The counter uses Django's configured cache;
the current LocMemCache is process-local (a shared cache is needed across workers).

## Auth & users (M4)
| Method | Path | Roles | Body → Response |
|---|---|---|---|
| GET | `/api/auth/csrf/` | public | sets the csrftoken cookie |
| POST | `/api/auth/signup/` | public | `{full_name, email, password, company?}` → 201 `User` (creates a `customer` user + linked Customer, logs in) |
| POST | `/api/auth/login/` | public | `{email, password}` → `User` |
| POST | `/api/auth/logout/` | any | 204 |
| GET | `/api/auth/me/` | any | `User` → `{id, email, full_name, role, customer_id}` |
| POST | `/api/auth/password-reset/` | public | `{email}` → always 204 (no account enumeration); emails a link `{FRONTEND_URL}/reset-password/{uid}/{token}` |
| POST | `/api/auth/password-reset/confirm/` | public | `{uid, token, new_password}` → 204 |
| POST | `/api/auth/change-password/` | any | `{old_password, new_password}` → 204 |
| GET/POST | `/api/staff/` | A | list / create internal user `{full_name, email, role: admin|staff, password}`. **Only admin can add staff.** |
| PATCH/DELETE | `/api/staff/{id}/` | A | deactivate instead of delete |
| CRUD | `/api/customers/` | A,S (C: own via `/me`) | `{id, name, company, email, phone, address, assigned_staff}`; `?search=` |

Password errors come back as `field_errors.password`, e.g. `"Must be more than 8 characters."`, `"Add an uppercase letter."`, `"Add a special character."`.

## Subscriptions (M3)
| Method | Path | Roles | Notes |
|---|---|---|---|
| GET | `/api/subscriptions/` | A,S,C(own) | filters `status, customer, plan, next_invoice_date__lte, search` (number / customer name) |
| POST | `/api/subscriptions/` | A,S | create draft `{customer, plan, start_date, expiration_date?, payment_term, discount?, notes, lines:[{product, variant?, quantity, unit_price?, tax_ids?}]}` (unit_price defaults to the variant/product price) |
| POST | `/api/subscriptions/from-template/` | A,S | `{template, customer, start_date}` → draft with the template's plan and lines |
| GET/PATCH | `/api/subscriptions/{id}/` | A,S (C read own) | PATCH only in draft; `status` is read-only |
| POST | `/api/subscriptions/{id}/{action}/` | see below | `action ∈ send, revise, confirm, activate, pause, resume, close, renew`; body `{note?, reason?}` → updated Subscription |
| GET | `/api/subscriptions/{id}/events/` | A,S,C(own) | timeline |

Customer actions in the portal: `confirm` (accept own quotation), `resume` (own paused subscription), `pause`/`close`/`renew` **only if the plan allows**. Everything else is A,S.

Subscription response:
```json
{"id": 41, "number": "SUB/2026/00041", "status": "active",
 "customer": {"id": 9, "name": "Asha Rao", "company": "Rao Traders"},
 "plan": {"id": 2, "name": "Growth Monthly", "billing_period": "monthly", "interval_count": 1},
 "start_date": "2026-10-01", "expiration_date": "2027-09-30", "next_invoice_date": "2026-11-01",
 "valid_until": null, "payment_term": {"id": 2, "name": "Net 15", "due_days": 15},
 "discount": null, "lines": [{"id": 1, "product": 3, "variant": 7, "description": "Brightloop CRM (Odoo)",
 "quantity": 5, "unit_price": "1760.00", "tax_ids": [1], "amount": "8800.00"}],
 "recurring_total": "8800.00", "allowed_actions": ["pause", "close"]}
```
`allowed_actions` is computed by the backend for the **current user**; the UI renders exactly those buttons.

## Billing / invoices (M3)
| Method | Path | Roles | Notes |
|---|---|---|---|
| GET | `/api/invoices/` | A,S,C(own) | filters `status, customer, subscription, overdue=true, invoice_date__gte/lte, search` |
| GET | `/api/invoices/{id}/` | A,S,C(own) | lines with tax snapshots, payments, `outstanding`, `is_overdue`, `changes` (vs previous invoice, BILLING_RULES §9) |
| POST | `/api/invoices/{id}/confirm/` · `/cancel/` · `/send/` | A,S | see BILLING_RULES §5 |
| POST | `/api/invoices/confirm-bulk/` | A,S | `{ids: [..]}` → `{confirmed: n}` |
| POST | `/api/subscriptions/{id}/invoice-now/` | A,S | bill the single due period now through the normal engine, no catch-up; `201` invoice, `400` `subscription_not_active` / `invoice_not_due` / `subscription_expired` / `invoice_already_billed` |
| POST | `/api/billing/run/` | A | `{date?, dry_run?: bool}` → `{activated, closed, invoiced, skipped, total_billed, discounts_applied, dry_run, ran_at}`; a dry run changes nothing |
| POST | `/api/internal/billing/run/` | Bearer `SCHEDULER_SECRET` | same, for the cron; constant-time secret compare |
| GET | `/api/billing/last-run/` | A,S | last run time + counts (shown on the Invoices page) |
